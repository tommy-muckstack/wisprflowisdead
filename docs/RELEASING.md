# Mac installer and automatic updates

Sparkle 2.10.0 is pinned by its official binary checksum. The app retains one `SPUStandardUpdaterController`, starts it after launch, and exposes Check for Updates in the menu bar. Automatic checking/downloading is enabled; profile reporting is disabled. Both the feed and archive require Ed25519 signatures.

`release/config.json` contains the public key, version, monotonically increasing build number, and stable HTTPS feed URL. Never replace that public key casually: installed copies trust it for future updates. Keep the signing private key backed up securely outside Git. This Mac stores it at `~/Library/Application Support/WisprFlowIsDead/Signing/update-ed25519.key`, with directory mode 700 and file mode 600 because Keychain access was unavailable during setup.

Run `bash scripts/package-release.sh` to create the installer selected by `release/config.json` (DMG for 0.1.1), update ZIP, signed appcast, and checksums under `.build/releases/<version>/`. `UPDATE_KEY_FILE` can select another protected key file. The default app is ad-hoc signed. Set `SIGNING_IDENTITY` (Developer ID Application) and `NOTARY_PROFILE` to sign and notarize a public DMG distribution. Local `INSTALLER_FORMAT=pkg` also supports packages, requiring `INSTALLER_IDENTITY` (Developer ID Installer) for notarization. No certificates or credentials are committed. The PKG installs into `/Applications` and disables bundle relocation; the DMG includes an Applications shortcut. Hosted publication requires the configured installer format and validates Developer ID/notarization for DMGs, so an ad-hoc PKG cannot be substituted for 0.1.1.

Verify the extracted PKG with `python3 qa/verify-native-app.py <app-path>` and the feed/archive with `swift scripts/verify-release.swift <release-directory>`. These inspect real bundled helpers, runtime linkage, resources, code signatures and cryptographic signatures. Verify a complete update/relaunch cycle on a logged-in Mac separately.

Normal publication: merge the reviewed source, create a GitHub release targeting that merged commit, and upload the configured DMG or PKG, ZIP, appcast and checksums without changing their bytes. After confirming the assets are available, copy the signed appcast unchanged to `updates/appcast.xml` on main. Do not publish a feed pointing to an unavailable archive. Never overwrite an existing version: increment both version and build for a new release.

If local GitHub CLI networking is unavailable, the GitHub connector can stage binary chunks on a separate `release/upload-*` branch. `.release-payload/manifest.json` records the merged source commit and every artifact's SHA-256/ordered chunk paths. The publishing workflow reassembles them, checks public-key signatures, the bundled app, and (for DMG releases) Developer ID/notarization/Gatekeeper trust, requires the source to be an ancestor of main, and creates the GitHub release. Binary staging branches are never merged into main. The private signing key never leaves this Mac.

The initial 0.1.0 installer is Apple silicon only, ad-hoc signed and not notarized. A Developer ID identity was unavailable. The website's 90+ home/pricing parity goal and real microphone/native visual checks remain outstanding.

## Reuse MyMan's Apple signing setup

MyMan's direct-release script uses Apple team `K8NAZ76CBQ` and the local notarytool profile `mumbls-notary`. Its installed app confirms that team and a stapled ticket. Use a valid Developer ID Application identity from that team as `SIGNING_IDENTITY`, and `NOTARY_PROFILE=mumbls-notary`. The PKG additionally requires a Developer ID Installer identity from the same team as `INSTALLER_IDENTITY`; MyMan's DMG process does not establish that an Installer certificate exists. [Apple documents the two certificate types](https://developer.apple.com/help/account/certificates/create-developer-id-certificates/).

The app signs with `release/WisprFlowIsDead.entitlements`, granting only the [audio-input access required by Hardened Runtime](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input). Sparkle helpers retain their own signing configuration. Keep WisprFlowIsDead's existing Sparkle public/private key pair: sharing an Apple team does not require sharing MyMan's update key.
